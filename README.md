# YAi Retro Camera — Этап 0

Android-прототип: задняя камера → отдельные куски со звуком → тёплый цвет и зерно → один MP4 в галерее. Без водяного знака и искусственного лимита записи. Всё видео обрабатывается на телефоне.

**Статус:** код Antigravity проверен и исправлен Codex. Проверки типов, тесты сессии/драйвера/моста, компиляция SkSL и генерация Android выполнены локально. Результат Android CI и ссылка на APK — в последней записи [REPORT.md](REPORT.md). Этап 0 остаётся неподтверждённым до проверки на реальном телефоне.

## Установка на телефон

Нужен Android 10 или новее, процессор ARM64 или ARMv7. Это тестовая сборка с обычной отладочной подписью; ключа магазина здесь нет. Приложение запускается без ПК, Metro, Expo Go, регистрации и сети.

1. На телефоне открыть [Releases](https://github.com/eai-apps/YAi-Retro-Camera/releases) → последний **Stage 0 test build**.
2. В **Assets** нажать `YAi-Retro-Camera-stage-0.apk` → скачать → открыть файл.
3. Если Android попросит: **Настройки** → разрешить установку для этого браузера/файлового менеджера → вернуться → **Установить**.
4. Открыть **YAi Retro Camera** → разрешить **Камеру** и **Микрофон**. Для своего нового ролика доступ ко всей галерее не нужен.
5. При отказе в разрешениях нажать **Открыть настройки** в приложении → **Разрешения** → включить камеру и микрофон → вернуться.

Если Releases пока пуст, сборка ещё не опубликована: [Actions → Build Android APK](https://github.com/eai-apps/YAi-Retro-Camera/actions/workflows/android.yml). Не скачивайте APK из посторонних источников.

## Проверка «три куска»

1. Убедиться, что в превью виден живой кадр с тёплым цветом и меняющимся зерном.
2. **ЗАПИСЬ** → снять 5–10 секунд, сказать «один» и хлопнуть в кадре → **ПАУЗА**. В ленте должен появиться кусок №1.
3. Подождать 3 секунды → **ПРОДОЛЖИТЬ** → снять «два» с хлопком → **ПАУЗА**.
4. Подождать 7 секунд → **ПРОДОЛЖИТЬ** → снять «три» с хлопком → **СТОП**. В ленте три куска.
5. **Склеить** → дождаться сообщения о сохранении → **Открыть ролик**. Также открыть видео самостоятельно из Галереи → альбом **YAi Retro Camera** (папка `Movies/YAi Retro Camera`).
6. Проверить порядок, отсутствие пауз в итоге, тёплый цвет и живое зерно во всех кусках, звук и совпадение хлопков с изображением у начала/стыков/конца. Для точной проверки целевой порог рассинхрона — 100 мс; без измерения сообщать только о видимом совпадении.
7. Отдельно проверить **СТОП → ПРОДОЛЖИТЬ**: добавляется новый кусок той же сессии. После перезапуска приложения готовая лента должна восстановиться.

Сообщите модель телефона, версию Android, что произошло, текст ошибки и результат просмотра из галереи. Пароли и личные видео отправлять не требуется.

## Как работает прототип

- VisionCamera 4.7.3 пишет исходные MP4/H.264 со звуком микрофона. Формат выбирается около 1280×720, 30 fps, SDR; при отсутствии точного формата используется ближайший поддерживаемый. Кадр не растягивается.
- Пауза/стоп ожидают `onRecordingFinished`; продолжение создаёт новый файл. Кусок проверяется через MediaMetadataRetriever, копируется с синхронизацией на диск в `files/retro_sessions/chunks/`. Длительность/размер читаются из файла.
- Skia Frame Processor обрабатывает настоящий кадр для превью. Кадры не проходят через JS/base64 и не записываются с экрана.
- Экспорт — локальный Kotlin/Media3, последовательная композиция, тёплый цвет и анимированное зерно, MP4/AVC/AAC. Общая формула `effects/warm-film.glsl` генерирует SkSL и GLSL. Различия цветопередачи конкретного телефона ещё требуют проверки, попиксельное совпадение не заявляется.
- Каталоги сохраняются нативным AtomicFile: отдельный JSON на сессию и `current.json`. При запуске файлы проверяются, незавершённые/недоступные не включаются в ленту. Ошибки сохранения не скрываются.
- Публикация в MediaStore происходит после полной записи/проверки размера; недописанная запись галереи удаляется при ошибке. Готовые исходники при этом сохраняются. Нет нативного экспортера — видимая ошибка, никакой подмены первым исходником.
- При уходе в фон приложение пытается финализировать текущий кусок и выключает камеру. Принудительное завершение процесса ОС может оборвать активный файл; уже готовые куски сохраняются.

В Этапе 0 нет удаления/перестановки кусков, просмотра архивных сессий, фото и других камер. «Новая съёмка» после сохранения начинает пустую ленту и оставляет старые исходники/каталог в приватном хранилище. Со временем они занимают место. Удаление приложения удаляет его приватные исходники; ролики, уже сохранённые в галерее, остаются.

## Воспроизводимая сборка

Каноническая среда CI: Ubuntu 22.04, Node 22, JDK 17, Android SDK/build-tools 35, NDK 26.1.10909125. Сборка не использует EAS и магазинные ключи. Точные npm-версии зафиксированы в `package-lock.json`; Media3 — 1.5.0. Локальные проверки Codex выполнены на Windows с Node 24.22.0; CI проверяет Node 22 отдельно.

В корне проекта (Windows: `npm.cmd`/`npx.cmd`; Linux: `npm`/`npx`):

```powershell
npm.cmd ci --no-audit --no-fund
npm.cmd run typecheck
npm.cmd run check:shaders
node scripts/check-shader.cjs
npm.cmd test -- --runInBand --no-cache
npx.cmd expo prebuild --clean --platform android --no-install
```

`prebuild --clean` пересоздаёт только генерируемую папку `android/`; не храните там ручные правки. Исходники модуля находятся в `modules/retro-export`, настройки Android — в `plugins/withStageZeroAndroid.js`.

Для локальной сборки с JDK/SDK:

```powershell
cd android
.\gradlew.bat assembleRelease --no-daemon --max-workers=2 -PreactNativeArchitectures=arm64-v8a,armeabi-v7a
```

Linux/CI: `cd android` → `./gradlew assembleRelease --no-daemon --max-workers=2 -PreactNativeArchitectures=arm64-v8a,armeabi-v7a`.
APK: `android/app/build/outputs/apk/release/app-release.apk`. Package id: `com.eai.retrocamera`, version: `0.1.0`; CI задаёт versionCode номером запуска, локально — 1. Release-вариант включает JS bundle и для теста использует стандартную debug-подпись Expo-шаблона. Это не сборка для магазина.

Если изменили формулу эффекта: `npm run generate:shaders`, затем проверки. `scripts/check-shader.cjs` действительно компилирует SkSL в Skia/CanvasKit; это не тест Android GPU.

Ручной CI: репозиторий → **Actions** → **Build Android APK** → **Run workflow** → ветка **main** → **Run workflow**. После зелёного запуска: **Code** → **Releases** → APK и SHA256SUMS. Не считать зелёный CI подтверждением работы камеры/звука на телефоне.
