## 5. Экран, запись и сохранность кусков

Простой интерфейс по-русски: превью; видимый статус и время текущей записи/сумма готовых кусков; кнопки «ЗАПИСЬ», «ПАУЗА», «ПРОДОЛЖИТЬ», «СТОП», «Склеить и сохранить»; горизонтальная лента с номером и фактической длительностью каждого куска. Миниатюры желательны, если их получение не усложняет основной путь. Сохраняй порядок записи.

Сделай явные состояния `idle`, `starting`, `recording`, `finalizing`, `paused`, `stopped`, `exporting`, `error` (можно эквивалентные названия). Действия сериализуй; быстрые двойные нажатия не создают двух записей/экспортов.

| Действие | Ожидаемое поведение |
|---|---|
| ЗАПИСЬ в пустой сессии | Начинается первый файл с видео и звуком |
| ПАУЗА во время записи | Закрывается текущий файл; после callback завершения проверяется и добавляется в ленту |
| ПРОДОЛЖИТЬ после паузы | Начинается НОВЫЙ файл в той же сессии |
| СТОП во время записи | Финализируется текущий файл, сессия остаётся с готовыми кусками |
| СТОП после паузы | Сохраняется список; пустой кусок не создаётся |
| ПРОДОЛЖИТЬ после СТОП | Можно дописать новый кусок в ту же ленту |
| Склеить и сохранить | Доступно при наличии готовых кусков и отсутствии активной операции |

Пауза — граница отдельных файлов. Одного вызова native pause/resume, который оставляет один файл, недостаточно. Ожидай именно фактического завершения записи, а не только возврата stop-запроса. В ленту не попадают нулевые, отсутствующие и незавершённые файлы. Длительность бери из результата/метаданных, а не только из UI-таймера.

Исходники храни в постоянной приватной папке приложения, отдельно от временных экспортов. Каталог сессии сохраняй атомарно (id, путь/URI, длительность, параметры), восстанавливай при повторном открытии. Не удаляй готовые исходники при ошибке, повторном экспорте, отмене или уходе в фон. Незавершённый файл после аварии проверяй отдельно и не считай валидным автоматически. Очистка — только явно выбранной сессии с подтверждением, без доступа к чужим файлам.

Разрешения: камера и микрофон с понятным объяснением; отказ и «больше не спрашивать» ведут к понятному сообщению/настройкам. На Этапе 0 для критерия готовности нужны оба разрешения: не выдавай тихое видео за запись со звуком. Если микрофон отключён, явно покажи это и предложи включить; запись без звука не подтверждает этап. Не запрашивай все файлы, контакты, геолокацию и лишние разрешения.

При уходе в фон/блокировке останови и финализируй активную запись насколько позволяет ОС; вернувшись, покажи состояние. Не продолжай скрытую съёмку. Обрабатывай потерю камеры/микрофона, исключения кодера и нехватку места без потери уже готовых кусков.

## 6. Реальный экспорт с эффектом и звуком

Локальный нативный модуль принимает упорядоченный список готовых исходников и конфигурацию эффекта. Экспорт выполняется нативно, вне JS UI-потока, с освобождением ресурсов при завершении и ошибках. Не перегоняй все кадры через JS/base64, не загружай ролик целиком в RAM и не записывай экран телефона.

Для предложенного варианта Б используй Media3 Composition/последовательность отредактированных медиа-элементов и Transformer. Нужна настоящая обработка кадров: тёплый баланс цвета плюс зерно в зависимости от времени кадра, например собственный GlEffect/GlShaderProgram. Неподвижная прозрачная картинка поверх UI зерно в файле не заменяет. Согласуй координаты, цветовое пространство и время зерна у превью/экспорта.

Выход — обычный MP4, H.264/AVC + AAC, SDR, единые согласованные размеры/FPS, корректная портретная ориентация и естественная скорость. В итог не включаются длительности пауз. Не склеивай MP4 простым соединением байтов. Не обходи перекодирование, если из-за этого исчезает эффект. Не используй сомнительные бинарники FFmpeg/FFmpegKit или сборки с непроверенной/GPL-лицензией.

Следи за временными метками видео и аудио, границами AAC, монотонным временем и стыками. Звук обязателен во всех трёх кусках, без пропусков/наложения и нарастающего рассинхрона. Целевой критерий проверки — расхождение хлопка и кадра не более 100 мс в начале, у стыков и в конце; укажи метод/точность измерения, а без измерения пиши только о визуальном наблюдении. Этот порог — требование прототипа, не гарантия библиотеки.

Показывай настоящий прогресс из экспортера (либо неопределённый индикатор, пока процент недоступен). Повторный экспорт не должен запускаться параллельно. Отмена, если добавлена, оставляет исходники и удаляет только собственный незавершённый выход.

Сохраняй готовое видео в общую галерею Android через MediaStore с корректным использованием scoped storage для поддерживаемых версий. Проверь фактические minSdk и требования разрешений; не требуй широкого доступа к галерее для записи своего нового ролика, если ОС этого не требует. Для Android 10+ используй безопасную публикацию через pending-запись/эквивалент: неполный файл не показывается как готовый; при ошибке удаляется только свой недописанный результат. Исходники остаются приватными. Успех показывай после завершения и проверки сохранения, с возможностью открыть итоговый URI внешним проигрывателем. Ошибка MediaStore — это ошибка сохранения, не успех.

## 7. Проверки и критерий готовности

Выполни доступные проверки. Не подменяй реальные результаты ожиданиями. Раздели в отчёте: статический анализ, автоматические тесты, локальная/CI-сборка, эмулятор, реальный телефон, подтверждение владельца.

1. Чистая установка `npm ci`, TypeScript/lint согласно конфигурации, сборка Android. Запиши команды, версии, exit code и существенные ограничения. Если SDK/телефона нет — прямо «не запускалось», с причиной и следующей командой.
2. Содержательные тесты логики сессии: pause/stop ждут финализации; повторные нажатия не дублируют куски; ошибка закрытия не добавляет файл; порядок исходников сохраняется; неудачный экспорт не стирает сессию; восстановление каталога не включает незавершённый кусок. Не тестируй только повторение реализации.
3. На реальном Android: установить автономный APK; отключить Metro/ПК и сеть; открыть приложение; разрешить камеру/микрофон; убедиться, что изображение живое и зерно движется.
4. Записать три куска примерно по 5–10 секунд: называть «один», «два», «три» и делать видимый хлопок в каждом. Между ними сделать разные паузы, например 3 и 7 секунд. Проверить путь ЗАПИСЬ → ПАУЗА → ПРОДОЛЖИТЬ → ПАУЗА → ПРОДОЛЖИТЬ → СТОП. Отдельно проверить СТОП → ПРОДОЛЖИТЬ без потери ленты.
5. Склеить и сохранить. Открыть именно файл из галереи другим проигрывателем: три куска в правильном порядке, эффекты видны во всех, зерно меняется, звук соответствует хлопкам, пауз нет, длительность соответствует сумме исходников с объяснённой погрешностью контейнера/кодера. Сравнить с приватным чистым исходником или контрольным кадром, чтобы подтвердить реально наложенный цвет.
6. Проверить отказы в разрешениях, быстрые нажатия, возврат из фона, перезапуск приложения с готовыми кусками и доступный сценарий ошибки экспорта. Без намеренного заполнения диска владельца. Не удалять его медиа.

**Этап 0 подтверждён только тогда, когда на настоящем Android три отдельных куска со звуком превращаются в один ролик с видимым эффектом, без заметного рассинхрона, и он воспроизводится из галереи независимо от приложения.** Зелёная сборка или красивое превью отдельно этого не доказывают. Если физического теста нет, статус: «код подготовлен; проверка на реальном телефоне ожидается», с точным перечнем выполненного. Не выдумывай модель телефона, время рендера, FPS и результаты.

## 8. Что сдать Codex

Оставь весь исходный проект в указанном корне, с lock-файлом, конфигурацией сборки, нативным модулем и ресурсами. Не сдавай только код в чате. Не включай node_modules, build-каталоги, личные ролики, секреты и keystore в передаваемые исходники.
